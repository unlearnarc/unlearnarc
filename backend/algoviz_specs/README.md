# Basic sorting and searching visualizers

`seed_basic_algorithms.py` owns eight complete array walkthroughs:

- Bubble, Selection, Insertion, Merge, Quick, and Heap Sort
- Linear and Binary Search

Each includes an explanation, prerequisites, stability/in-place properties, time/space
bounds, a concrete input/output example, and complete Java and Python functions.
The database uses the existing algorithm API; no schema migration is needed.
Other algorithm slugs (graphs, stack, matrix, etc.) are not modified.
Existing matching sorting/searching slugs are updated **in place**, keeping their IDs.

## Validate offline

From `backend/`:

```sh
python3 seed_basic_algorithms.py --export
python3 -m unittest test_seed_basic_algorithms.py -v
```

Export regenerates the eight checked-in JSON files; it does not contact the database.
Tests run both Python and Java examples on empty, singleton, duplicate, negative,
sorted, reversed, absent-target, and deterministic randomized cases. A JDK is
required for Java execution (otherwise that test is skipped).

## Populate the local database

Start the backend, then run from `backend/`:

```sh
python3 seed_basic_algorithms.py
```

The script defaults to the same local development admin credentials as the existing
seed scripts. Override them with `ADMIN_EMAIL` and `ADMIN_PASS`. `BASE` defaults to
`http://localhost:8085`; explicitly configure it to target a different backend.
Credentials and access tokens are never printed.

All eight payloads pass server-side dry-run validation before any database write.
The script creates missing slugs, updates changed payloads, publishes, re-fetches
and compares every authored field, and verifies the published feed. An unchanged
rerun does not update versions or create duplicates. A failed run can be retried;
it is not a transaction across all eight algorithms.

## Interaction and trace semantics

Open `/algorithms` in the student app. Use Play/Pause, Previous/Next, the timeline,
and speed control. Each algorithm has two prediction checkpoints. Answers show
feedback and the expected answer; learners can then continue even after a wrong
answer. Restart clears answers. Timeline seeking remains available for review.

Python is the default synchronized source for this pack. Every recorded frame is
the state **before** the highlighted Python line executes. Traces are generated by
executing the exact displayed implementation, rather than hand-written snapshots.
Sorting finishes at the fully sorted array; search finishes at the returned index.
Java tabs provide equivalent implementations, not line-mapped translations.

The examples use fixed small positive inputs so the existing array bar renderer is
clear. Implementations are also tested on negative values; this pack does not add
custom-input trace generation. Merge/insertion writeback may temporarily duplicate
values in the main array, with originals retained in local copies/the saved key.

Do not rerun the older `seed_algoviz.sh` or `seed_algoviz_starter.sh` after this pack
unless you intend to restore their shorter legacy examples. If you use those scripts,
run `seed_basic_algorithms.py` last to restore the complete content.
