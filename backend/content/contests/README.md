# Topic practice contests

Four public, untimed topic contests: **Arrays, Hash Maps, Sets, Linked Lists**.
Each has **15 Easy + 15 Medium + 15 Hard = 45 questions** (180 total).
Easy/Medium/Hard award 100/200/300 points. Each question includes two public
samples and six hidden cases: **1,440 cases (360 public / 1,080 hidden)**.

The bank covers common interview-practice patterns: two pointers, prefix sums,
sliding windows, frequency maps, set membership, graph frontiers, monotonic stacks,
interval DP, list reversal, merging, cycles, and linked cache designs. These are
curated classics and instructional variants, not an externally verified ranking
of company interview frequency. Difficulty is relative to this practice track;
some advanced-track exercises are rated Medium on other platforms.

Original statements explicitly document JSON fields, sentinels and tie-breaking.
Some enumeration exercises request counts instead of collections to keep stdout
grading deterministic. Inputs are JSON objects on stdin; list answers are
space-separated, or `EMPTY`. Exact median exercises return **twice the median**.

Only Python is enabled because the current browser runner supports its stdin.
Linked-list requirements call for actual nodes, but stdout cannot enforce node
identity, pointer usage or auxiliary space. Serialized cycles, shared suffixes,
random pointers and nested child chains have explicit contracts.

## Validate and populate

From `backend/`:

```sh
python3 seed_topic_contests.py --validate
python3 -m unittest -v test_seed_topic_contests.py
read -s ADMIN_PASS; export ADMIN_PASS; echo
python3 seed_topic_contests.py --expand-published
unset ADMIN_PASS
```

`BASE` defaults to `http://localhost:8085`; `ADMIN_EMAIL` defaults to the existing
local seed administrator. No password is stored in the Python scripts.

New contests start as drafts and publish only after re-fetching and comparing
all authored fields and test cases. `--draft` leaves new contests unpublished.
The four original slugs and their first three questions remain unchanged; new
questions follow them, ordered Easy, Medium, Hard. Re-runs reuse exact titles,
never overwrite/delete problems or their test cases, and create no duplicates.

Published-contest expansion requires explicit `--expand-published` and **zero
participants**. Archived contests, changed existing content, unexpected titles,
and ambiguous duplicates are refused. API additions preserve existing question
IDs; no status downgrade is needed. Failed additions can be resumed by rerunning.
Do not run concurrent seed processes: the API has no atomic idempotency key.
The original `seed_contest.sh` is unchanged.

## Content and test design

`topic_practice_bank.py` supplies 168 additions, clear reference computations,
336 hand-authored public expected answers checked against those computations,
and six distinct hidden fixtures per addition. Hidden outputs are generated by
the reference computations, not an independent judge; the tests also include
independent known answers and graph cross-checks for selected advanced oracles.
The original 96 cases retain their independent reference checks and large-input
boundary fixtures. New fixtures emphasize empty/singleton inputs where allowed,
duplicates, signs, missing solutions, ties, and representative multi-step cases;
not every new problem has a maximum-constraint performance fixture.

The unit suite exercises catalog counts, original expected outputs, sample
answers, known advanced answers, draft resumption, published expansion,
participant protection, drift detection, and read-only idempotent re-runs.
Reference implementations favor auditability over optimal performance on small
fixtures and are never submitted as student starter code or sent to the API.
